# MyoPilot browser automation: work done so far

Status as of Saturday 7 November 2026 (HackTheBurgh XIII, Edinburgh). Owner of this part: Karthik.

---

## 1. What we are building

**MyoPilot** helps people with motor disabilities who can't comfortably use a mouse and keyboard. Muscle (EMG) gestures are decoded into a small set of commands, and those commands drive a browser that does everyday web tasks.

One project, three hackathon tracks:

| Track | Challenge | How MyoPilot fits |
|---|---|---|
| **Wordsmith** | Most complicated end-to-end agentic AI browser-use workflow. Judged mainly on workflow complexity; tokens used, model used and time to complete also count | A LangGraph agent completes multi-step tasks on live websites (search, read, fill multi-page forms, ask the user, approve, submit) |
| **G-Research** | Make the invisible visible | Hidden muscle signals become visible, usable commands |
| **HRT** | Best use of data for predictions and decision making | A real-time EMG classifier turns raw signals into decisions |

**Split of work**
- **Suvrit:** the EMG classifier (`emg_data/`, `models/`, notebooks). It uses NinaPro DB5, replayed as a stream; we have no live hardware.
- **Karthik:** the browser automation, everything in `browser_automation_agent/`, plus connecting it to Suvrit's classifier.

**Honesty rule for the demo:** the EMG is **recorded** NinaPro data, replayed in real time. The classification happens live; the signal itself is not live.

## 2. Decisions and how they changed

| Topic | Decision | Notes |
|---|---|---|
| Focus | **Accessibility**, not legal | Early drafts used a legal due-diligence workflow, because Wordsmith is a legal-AI company. The user corrected this: the product is for people with disabilities |
| Websites | **Live public websites** (NHS, GOV.UK), plus one local demo form | The demo form exists only to show the full approve-then-submit path, which we block on live sites |
| Interaction | **Switch access**: four commands move through menus. One "select" can start a long autonomous task | Builds on a real assistive-technology pattern |
| Typing | **Layered**: (1) profile autofill, (2) turn questions into choices, (3) voice only for free text | Voice uses the browser's Web Speech API in the panel |
| Framework | **LangGraph** | Chosen by the user. Every wait for the user is a LangGraph `interrupt()` |
| LLM | **AWS Bedrock**; the model is the user's choice | Currently `amazon.nova-pro-v1:0` in `eu-west-2` (see section 6) |
| Browser | **Playwright driving the installed Google Chrome** | Set with `MYOPILOT_BROWSER=chrome`; `chromium` uses Playwright's bundled browser |
| Environment | **uv**, one project for the whole repo | One `pyproject.toml`, `uv.lock`, `.venv`, `.env` and `.gitignore` at the repo root |
| Commands | **Suvrit's names**: `scroll_down`, `scroll_up`, `forward`, `back` | Our earlier names (NEXT/PREV/SELECT/BACK) were removed, so the two pipelines need no translation |

## 4. How the browser automation works

### 4.1 Switch access
- **Home screen** lists everyday tasks:
  - Find a pharmacy near me (NHS)
  - Register with a GP (NHS)
  - Check train times (National Rail)
  - Today's weather (BBC)
  - Book community transport (local demo form)
  - Something else (speak)
- **Commands:** `scroll_down` / `scroll_up` move the highlight, `forward` selects, `back` cancels or goes back.
- Selecting a task runs the LangGraph agent until it finishes. The **result** screen then shows the answer and LLM-suggested follow-ups.
- `back` from a result opens the **browse** screen. There the LLM proposes 3–4 actions for the current page, plus Scroll down, Scroll up, Home and Something else.
- Commands that arrive while the agent is working are dropped on purpose, so a stray gesture can't trigger a surprise action.

### 4.2 The LangGraph agent
- **Each step:**
  1. The model sees the page as `URL / TITLE / HEADINGS / ELEMENTS [ref] … / PAGE TEXT`.
  2. It calls exactly one tool, with a plain-English `explain` caption.
  3. The tool result is the fresh page.
- **Talking to the user:** `ask_choice`, `ask_text` and `confirm` pause the graph with `interrupt()`. The session turns that into a menu, a voice prompt or an Approve / Don't submit choice, then resumes the graph with `Command(resume=…)`.
- **Prompt trimming:** only the latest 2 page snapshots go to the model in full; older ones shrink to one line. The stored state keeps everything for the log.
- **Event log:** every step is logged with tool, args, URL, ok/error, latency, screenshot, and whether typed text came from the profile. Every LLM call is logged with model, latency, and input/output/cache tokens.

### 4.3 Typing in layers
1. **Profile autofill** (`profiles/demo_user.json`). The fictional persona is Alex Morgan, address The British Library, 96 Euston Road, London NW1 2DB. That is a public building, chosen because NHS "Find a GP" only covers England. Date-of-birth parts (14 / 03 / 1990) count as profile values.
2. **Choices.** Dropdowns, radios and predictable answers become `ask_choice` menus.
3. **Voice.** Truly free text uses `ask_text`, answered by voice in the panel (V key / mic button; Chrome needed) or typed for development.

### 4.4 Control panel (http://localhost:8765)
- Large menu cards with the highlighted item in orange; screens for working, ask, confirm, text and result.
- Buttons ▲ scroll_up, ▼ scroll_down, ● forward, ↩ back. Keys: ↓/→ scroll_down, ↑/← scroll_up, Enter forward, Esc back, V voice.
- Live log of every gesture, EMG decode, LLM call (tokens and latency), browser step, ask, answer and result.
- Metrics: browser steps, LLM calls, tokens, elapsed time, model.
- Extra endpoints: `POST /intent/{command}` (for other processes) and WebSocket `/ws`.

## 5. Safety, enforced in code (not just the prompt)

**SafetyGuard** (`safety.py`)
- **Domain allowlist:** nhs.uk, gov.uk (including *.service.gov.uk), nationalrail.co.uk, bbc.co.uk, wikipedia.org, localhost. A click that leaves these sites (for example a Google Maps link) is undone automatically.
- **No secrets:** never types into password, PIN, card, CVV, sort-code or account-number fields (checked by type, autocomplete attribute and label).
- **Submit needs approval:** any submit-like button (or "Continue" on a check-your-answers page) needs a fresh `confirm()` approval. One approval allows one submit.
- **Live demo mode** (`MYOPILOT_LIVE_NO_SUBMIT=true`): on live sites the final submit is **always** blocked, even if approved. The agent stops at the review page and tells the user the form is ready to submit.

**ProvenanceGuard** (`provenance.py`)
- **What it allows:** the agent may only type or choose values that came from the **profile**, the **task the user chose**, or the **user's own answers**. Radio and checkbox choices must match something the user said, unless they come from the profile (for example "England").
- **Why it exists:** Nova Pro was observed inventing a travel date, a wheelchair answer and a specific hospital (St Mary's, Praed Street) that the user never mentioned. A prompt rule alone did not stop it.
- **What happens on a refusal:** the tool result says `NEEDS USER INPUT` and includes a ready-made `ask_choice(...)` built from the page's own options, so the model asks instead of retrying.
- Can be turned off with `MYOPILOT_STRICT_PROVENANCE=false`.

**Other safeguards**
- Cookie banners: the agent always rejects analytics cookies.
- Only a fictional persona is used. The demo form is unbranded and labelled "not a real service".

## 6. LLM / AWS Bedrock journey

| Step | What happened | Outcome |
|---|---|---|
| 1 | `.env` had `AWS_PROFILE=` (empty), so boto3 looked for a profile named "" | Fixed: empty AWS variables are treated as unset |
| 2 | `anthropic.claude-haiku-5-5` returned "not available for this account" | Needs the inference-profile ID `us.anthropic.claude-haiku-5-5` |
| 3 | Still refused | The account's **model agreement status was `NOT_AVAILABLE`** for Haiku 5.5 and most Claude models in us-east-1. Only Sonnet 4.6 was enabled. Enabling it is a console step for the account owner, and it was not completed |
| 4 | Switched to **Amazon Nova Pro** (`amazon.nova-pro-v1:0`, `eu-west-2`) | Works |

### Fixes made while testing with Nova Pro
1. **Snapshot bug (affected every model).** `page.evaluate` passes one argument, but the snapshot function took two. The page-text limit fell back to 120 characters, so the model never saw most of each page and scrolled around blindly. **Fixed**: it now gets the full text (capped at 3,500 characters) and an element cap.
2. **Vague answers.** Nova sometimes put the real answer in plain text and "the details have been provided" inside `finish()`. The agent now keeps whichever carries more information, and the prompt requires real facts in the answer.
3. **Tool calls written as text.** Nova sometimes writes `<finish answer="…"/>` as text. Such text is now parsed back into a real tool call, and the prompt forbids it.
4. **Options menu.** Nova strips the leading underscore from schema names (`_Options` became `Options`), so parsing failed. The schemas were renamed to `MenuOptions` / `MenuOption`.
5. **Invented values.** Solved by the ProvenanceGuard (section 5).
6. **Unnecessary scrolling.** The prompt now says the page text already covers the whole page and off-screen elements can be clicked directly.

## 8. Connecting Suvrit's classifier

### 8.1 What Suvrit built (`emg_data/`)
1. **Replay** (`stream.py`): real "rest, then gesture" pieces from NinaPro DB5 Subject 1, Exercise 2, joined and played back like a sensor. One window per 125 ms (50 samples × 16 channels at 200 Hz).
2. **Features and model** (`emg.py`, `model.py`): MAV, RMS and waveform length (48 features), classified by LDA into rest (0), fist (6), spread fingers (5), wrist radial (15) and wrist ulnar (16). The model `models/subject1_set_a.joblib` was trained on repetitions 1–5; repetition 6 is held out for the replay.
3. **Commands** (`commands.py`): majority vote over 5 windows, confidence of at least 0.9, 1 s cooldown for back/forward. Scroll commands **repeat every 0.3 s while held**.
4. **Interface** (`interface.py`): `replay_commands()` yields every window with an optional `event` (`t`, `command`, `gesture`, `confidence`).

### 8.2 Verified on this machine
- `data/s1/S1_E2_A1.mat` is present. The model loads with scikit-learn 1.9.1, the same version it was saved with.
- The full replay (285 windows, 35.8 s of signal) decoded all four gestures correctly at confidence 0.955–1.000.
- It also confirmed the repeat behaviour: **one held fist gave 7 `scroll_down` commands**.

### 8.3 How the link works (`emg_source.py`)
- Runs `replay_commands()` in the same process (same uv environment), one gesture piece at a time, in real time (`speed=1.0`).
- **Repeats:** only the first command of each gesture is forwarded by default (one fist = one `scroll_down`). `--emg-repeat` keeps Suvrit's behaviour.
- **Timing:** each gesture is performed only when a menu is waiting for input, so commands are never lost while the agent works.
- **Paths:** the model and data are found from the repo root, so it works from any folder.
- **Honesty:** whatever the model decodes is forwarded, even if it differs from the intended gesture; both are logged (`emg_command`, `emg_gesture_start/end`).

```bash
uv run main.py --emg                                   # the model's gestures in recording order
uv run main.py --emg --emg-sequence forward            # pick gestures by command name...
uv run main.py --emg --emg-sequence fist,fist,ulnar    # ...or by gesture name
```

### 8.4 One shared command vocabulary

| Command | Gesture | In MyoPilot menus |
|---|---|---|
| `scroll_down` | fist (6) | highlight down |
| `scroll_up` | spread fingers (5) | highlight up |
| `forward` | wrist ulnar deviation (16) | select / approve |
| `back` | wrist radial deviation (15) | cancel / go back |

The same names are used by the bus, the panel buttons and keys, HTTP (`POST /intent/scroll_down`), the WebSocket and the logs. A test checks that our list matches Suvrit's `COMMAND_FOR_GESTURE` exactly.

## 10. How to run

```bash
cd /Users/karthikmandigiri/HacktheBurgh
uv sync                                  # once
uv run playwright install chromium       # once (only needed for MYOPILOT_BROWSER=chromium)
cp .env.example .env                     # once, then set MYOPILOT_MODEL_ID and AWS_REGION

uv run main.py                           # full app with the LLM; panel at http://localhost:8765
uv run main.py --fake                    # no AWS: scripted stand-in model (pharmacy task only)
uv run main.py --emg --emg-sequence forward   # driven by Suvrit's classifier
uv run pytest -q                         # tests
```

Single task from the terminal:
```bash
PYTHONPATH=browser_automation_agent uv run python -m myopilot.cli_task "find a pharmacy near me and tell me its phone number" \
  --start-url https://www.nhs.uk/service-search/pharmacy/find-a-pharmacy --headed
```

Each run writes `browser_automation_agent/runs/<date-time>/events.jsonl` plus screenshots. The event schema is in `docs/integration.md`.

| Variable | Current value | Meaning |
|---|---|---|
